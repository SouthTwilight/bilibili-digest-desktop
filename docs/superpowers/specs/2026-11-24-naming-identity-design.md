# 文件命名与身份 设计文档

日期：2026-11-24
状态：已实现，待用户验收

## 背景与目标

三个月里至少八起文件名事故（见文末索引）。每次只补一个点，又引出下一个，因为病根没动：

- **起名分散在七处**，各自从接口标题、页面标题、文档 H1 或文件名推导，截断顺序不同。
- **查找时换个来源重算**：「已有总结」按导出文件名算期望名，总结却按 H1 命名，路径一深就永远对不上。
- **同一视频的目录被导出、笔记、总结各算一遍**，一触发长度截短就分叉成两个目录。

触发本次改造的事故：`_Pn` 先拼在 60 字标题后面，又被第二次 60 字截断切掉，一个 94 分P视频的所有总结写进同一个文件，93 份被覆盖。

目标：**不管名字多长、怎么来的，都不会互相覆盖、不会找不到**；同时新视频的名字短且可读。

用户已确认的决策：

- 目录结构和现有文件名外观不变；现有目录和总结不改名。
- 超过 30 字的标题用文本模型一次浓缩到 16 字以内，只对新视频生效。
- 总结包（zip）的导入本次不做。
- 历史遗留直接清理：放错名的总结改名；解压产生的重复目录移到库外备份目录。

## 设计原则

1. **身份只放在后缀里。** 视频靠 `_BV号`，文档靠 `_Pn`（无标记即 P1），种类靠 `AI总结_`、`笔记_` 前缀。
2. **起名只在一个模块。** 名字 = 标题段 + 结构后缀，截断只作用于标题段。
3. **名字只定一次。** 视频第一次进库时定下目录名，之后一律按 BV 号找目录；目录里文件的标题段取自目录名。
4. **查找按身份，不重算。** 有没有总结 = 同目录下有没有同一分P标记的 `AI总结_` 文件。
5. **一个路径预算。** 建目录时统一预留最小文件名的空间。

## 组件设计

### 1. 命名模块（`src/main/core/naming.js`）

唯一把标题变成名字的地方。

- `composeName(标题段, 上限, …后缀)`：唯一的拼名入口。标题段按码点截断（不切 emoji），不留末尾空格或点（Windows 会丢掉它们，磁盘上的名字就对不上了）。
- `identityHead`：去掉会被读成标记的结尾（`_P12`、`_BV…`、`_全部P`、时间戳），包括被截断切出来的残缺形式。
- `parseDocName(文件名)` → `{ kind, head, part, stamp, ext }`。`part` 把无标记和 `_P1` 归为同一身份 `p1`。
- `videoDirName`、`collectionDirName`、`exportDocBase`、`summaryBase`：各类名字的构造函数。
- `export-render.js` 的 `sanitizeName`、`exportFileName` 和 `notes.js` 的 `videoFolderName` 改为调用它；重复的 `sanitizeDirName` 已删除。

### 2. 路径预算（`src/main/core/paths.js`）

- 全路径上限 245（给 MAX_PATH 260 留余量）。超限时先截文件名，再从深到浅截文件夹；`_Pn`、`_全部P`、时间戳、扩展名、`_BV号`、`P{n}` 文件夹永不被截。
- `fitDirUnder`：建目录时按文件夹规则截短，并预留 `MIN_FILE_RESERVE`（分隔符 + 16 字下限 + `_Pn` + 时间戳 + `.html`）。导出不会遇到一个连最短文件名都放不下的目录。
- `assertFits`：实在放不下时抛 `PATH_TOO_LONG`，提示换更浅的保存目录，不再是一句 ENOENT。

### 3. BV 索引与目录定位（`library.js`、`notes.js`）

- `indexVideoDirs(saveDir)`：BV → 目录列表，扫保存目录下两层，BV 不分大小写。每次都现扫（几百个视频约 7 毫秒），所以用户在资源管理器里改名或移动目录后立刻生效，没有缓存过期窗口。
- `videoDirCandidates` / `findVideoDir`：同一 BV 有多个目录时，优先有字幕文档的，其次文件多的。
- `ensureVideoDir(context, decideVideoHead)`（异步，写路径）：有目录就复用，没有才新建。目录自己决定布局：已有 `P{n}` 子目录就继续用；顶层的独立目录在多P上下文写入且还没有平铺文档时开始用。
- `resolveVideoDir`（同步，读路径）保留，先按 BV 找，找不到再按上下文计算。
- 导出队列的 `exportTargetPath` 和笔记的 `add` 都走 `ensureVideoDir`。

### 4. 导出与总结

- 导出文件名的标题段取自目录名（`videoHeadOf`），不再各自从标题算。
- 总结的输出路径由 `summaryTargetFor` 决定：同目录已有同一分P标记的总结就写它（重跑原地覆盖，不改用户可能已经链接过的文件名）；没有才新建 `AI总结_文档名.md`。**总结文件名取自文档文件名，不再从 H1 推导。** 给模型看的标题仍是 H1 加 `_Pn`，标记拼在截断之后。
- `summarizeFileEntries` 的 `hasSummary` 改为按分P标记匹配。
- `markExported` 改用 BV 索引，分P标记只认文件名末尾，`P{n}` 子目录也算已导出，重复目录里的分P取并集。
- 批量总结里重名的文档会被编号，不再被拼进同一份。
- `summary:enqueue` 拒绝对 `AI总结_*`、`笔记_*` 文件做总结。

### 5. 超长标题浓缩（`src/main/core/title-condense.js`）

- 标题超过 `CONDENSE_ABOVE`（30）字时调用一次文本模型（temperature 0，8 秒超时），结果清洗后压到 `CONDENSE_MAX`（16）字以内。提示词在 `src/main/prompts/naming.md`。
- 降级：设置关闭、没配 Key、请求失败、超时、结果不可用，都回退到 60 字截断。导出不因此失败。
- 去重：同一标题的并发请求只发一次；同一视频本次会话内只定一次名。
- 设置项 `condenseLongTitles`，默认开启，设置页可关。
- 合集名和 UP 主名不浓缩：它们没有 BV 这样的身份，模型结果不确定会让同一合集裂成两个目录。

## 行为变化（相对旧版）

1. 总结文件名取自文档文件名。文档名被路径预算截短时，总结名跟着变短，而不是保留 H1 的前 60 字。
2. 重跑总结覆盖已有文件并沿用其文件名。
3. 「已有总结」按分P标记匹配，文件名标题段不一致也能认出来。
4. 一个视频在全库只有一个目录，先建的为准。第一个目录名不理想时，后续写入继续用它，不会再建第二个；手动改名或移动目录后应用照样找得到。
5. 对总结、笔记文件不能再做总结。
6. 路径放不下时提示「保存路径超过 Windows 的 260 字符限制」。
7. 视频标题恰好是「AI总结」或「笔记」时，导出文件名加「视频_」前导，避免被读成另一种文件。

## 不变量（由测试保证）

- `tests/naming.test.mjs`：标题长度 0–300 逐个长度，加对抗性标题（含 `_P12`、`BV1x4`、emoji、末尾空格和点、非法字符），断言后缀完好、写出的名字能原样读回。
- `tests/paths.test.mjs`：保存目录深度 0–200 逐档 × 纯汉字 / 含 emoji / 带空格的长文件名，断言能放下就一定放得下、不切 emoji、后缀不丢。
- `tests/library-identity.test.mjs`：先导出后记笔记、先记笔记后导出、深路径被截短、手动移动目录，四种情况落到同一个目录；总结按身份定位；以及回归用例——真实的 80 字标题 × 94 个分P × 文件名被截短的目录深度，94 份总结各带正确的 `_Pn`。
- `tests/title-condense.test.mjs`：阈值、结果清洗、各种降级、并发去重、接入目录定位。
